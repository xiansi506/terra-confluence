# 泰拉凝炼使用教程

[返回项目首页](../README.md)

## 安装

1. 准备运行 Java 17 的 **Minecraft 1.20.1 / Forge** 实例。当前构建使用 Forge 47.2.0。
2. 从 [Releases](https://github.com/xiansi506/terra-confluence/releases) 下载发布附件中的 `terra-confluence-1.0.20.jar`，放入实例的 `mods/`。
3. 安装 **Botania Forge 1.20.1**、**Patchouli** 和 **Curios API**。当前编译使用 Botania 1.20.1-455 Forge，其依赖要求是 Patchouli 1.20.1-83 或更新版，以及 Curios 1.20.1-5.4.2 或更新版。下载时都选择 Minecraft 1.20.1 的 Forge 文件。[Botania](https://modrinth.com/mod/botania/versions?g=1.20.1&l=forge) · [Patchouli](https://modrinth.com/mod/patchouli/version/1.20.1-83-forge) · [Curios API](https://modrinth.com/mod/curios/versions?g=1.20.1&l=forge)
4. 按需安装 **JEI** 查看配方。需要用脚本写配方时，再安装 **KubeJS 6** 及其要求的 **Rhino** 和 **Architectury API**。[JEI](https://modrinth.com/mod/jei/versions?g=1.20.1&l=forge) · [KubeJS](https://modrinth.com/mod/kubejs/version/2001.6.5-build.26%2Bforge)
5. 联机时，服务端和客户端都需要安装泰拉凝炼 1.0.20，以及匹配的 Botania 依赖。1.0.20 更新了配方同步格式，升级时两端应一起替换旧版。数据包或 KubeJS 配方放在服务端对应位置。

## 第一条配方

这条练习配方消耗 **2 颗黏土球**和 **5,000 魔力**，产出 **1 块红砖**，同时把凝聚板正下方的**石头**转化成**圆石**。选择数据包和 KubeJS 中的一种方式添加。

### 方式一 · 数据包

在存档的 `datapacks/` 里创建以下目录。专用服务端使用对应世界目录下的 `datapacks/`。

```text
datapacks/
└── terra_confluence_demo/
    ├── pack.mcmeta
    └── data/
        └── terra_demo/
            └── recipes/
                └── clay_brick.json
```

`pack.mcmeta`

```json
{
  "pack": {
    "pack_format": 15,
    "description": "Terra Confluence demo"
  }
}
```

`data/terra_demo/recipes/clay_brick.json`

```json
{
  "type": "terra_plate_extension:terra_plate",
  "ingredients": [
    { "item": "minecraft:clay_ball" },
    { "item": "minecraft:clay_ball" }
  ],
  "mana": 5000,
  "output": { "item": "minecraft:brick", "count": 1 },
  "below": { "center": "minecraft:stone" },
  "result_blocks": [
    { "x": 0, "z": 0, "block": "minecraft:cobblestone" }
  ]
}
```

进入世界后用有权限的账号执行 `/reload`。可以用 `/datapack list enabled` 核对数据包是否启用。

### 方式二 · KubeJS

在实例的 `kubejs/server_scripts/` 新建 `terra_confluence_demo.js`，填入下方脚本，然后进世界执行 `/reload`。

```js
ServerEvents.recipes(event => {
    event.recipes.terra_plate_extension.terra_plate({
        ingredients: ['minecraft:clay_ball', 'minecraft:clay_ball'],
        mana: 5000,
        output: { item: 'minecraft:brick', count: 1 },
        below: { center: 'minecraft:stone' },
        result_blocks: [
            { x: 0, z: 0, block: 'minecraft:cobblestone' }
        ]
    }).id('terra_demo:clay_brick')
})
```

### 在游戏里合成

1. 把泰拉凝聚板摆在一块**石头**上。本例只检查中心那一格，周围八格随意。
2. 在凝聚板上放一个**火花**，再在附近已经存有魔力的**魔力池**上放一个火花。
3. 往凝聚板上丢**恰好两颗黏土球**。板上多出的物品会影响匹配。
4. 等魔力充足后，捡起红砖，并检查正下方的石头是否已变成圆石。再做一次前，把圆石换回石头。
5. 装了 JEI 时，查看红砖的配方并切换到「泰拉凝炼」类别。左右平台分别展示条件和转化结果。

## 扩展配方

`ingredients` 中每个条目消耗一件物品，可使用 `{ "item": "…" }` 或 `{ "tag": "…" }`。需要两件相同物品时，写两个条目。`mana` 指定消耗，`output` 用物品对象表示，可以带 `count`。魔力消耗必须是非负数。大批量产物会按物品的堆叠上限分开掉落，每条配方最多产出 64 堆。

### 平台坐标和条件

平台坐标以凝聚板正下方为原点。`x` 向东为正，`z` 向南为正，两者范围都是 `-1` 到 `1`。`y` 可以省略，填写时固定为 `-1`。配方会尝试四个直角朝向。方块状态的朝向和转化结果会随命中的布局一起旋转。

| 写法 | 含义 |
| --- | --- |
| `below.center`、`corners`、`edges` | 指定中心、四角或四条边的中点 |
| `below.layout` + `below.block` | `3x3` 为九格、`cross` 为十字五格、`ring` 为外围八格。当前版本的 `diamond` 等同于 `3x3` |
| `below.exclude` | 从快捷布局和分组条件中排除坐标 |
| `below.positions` | 逐格指定规则，可以覆盖快捷布局或分组条件 |
| `result_blocks` | 逐格指定合成后的转化结果 |
| `transform_all` | 统一转化其余参与匹配的格子。`result_blocks` 优先 |

方块条件可写成 ID，也可检查具体状态。下面是 `below.positions` 中的单格例子。

```json
{ "x": 1, "z": 0, "block": { "id": "minecraft:redstone_lamp", "state": { "lit": "true" } } }
```

### 流体

在 `below.positions` 中用 `fluid` 代替 `block`。例如这格只接受流动水。

```json
{ "x": 1, "z": 0, "fluid": "minecraft:water", "flowing": true }
```

`source: true` 匹配源头，`flowing: true` 匹配非源头，两者都省略时仅检查流体种类。`result_blocks` 和 `transform_all` 也能指定流体，省略限定符时会放置源头。逐格示例见[流体脚本](../kubejs-examples/terra_plate_flowing_water.js)。

## 排查

| 现象 | 检查 |
| --- | --- |
| JEI 中找不到示例配方 | 确认 `terra_demo:clay_brick` 已随数据包或脚本加载。查看 `logs/latest.log`，检查 JSON 错误、错误目录和缺失依赖。 |
| 提示平台条件不满足 | 检查凝聚板正下方一层的石头是否已变成圆石，并核对配方坐标或方块状态。 |
| 板上有材料却不合成 | 清掉多余物品，确认凝聚板和附近有魔力的魔力池都装了火花。 |
| 游戏提示依赖缺失 | 按报错检查 Forge、Botania、Patchouli、Curios 的 Minecraft 版本与加载器。装了 KubeJS 时也检查 Rhino 和 Architectury API。 |

仓库中的 [KubeJS 示例](../kubejs-examples/) 用于演示配方写法。复制到正式整合包前，请按整合包的进度与平衡调整投入和产出。
